## 2. 安装步骤

### 2.1 Python 依赖
```bash
cd D:/DataMind
D:/python3.12.10/python.exe -m pip install -r agent/requirements.txt -r backend/requirements.txt
```
ETL 另需 PySpark：`D:/python3.12.10/python.exe -m pip install pyspark==3.5.3`。

### 2.2 MySQL
- 安装 MySQL 8.4.11，服务名为 `mysql`（本机已设为开机自启）。
- 首次部署按 `docs/mysql_readonly_init_template.sql` 创建只读账号（见第 4 节）。
- 数仓表由 ETL 脚本用写入账号（各 `etl/*/build_*.py` 顶部配置，通常 root）建立；
  本文不重复 ETL 建库步骤，数据完整时无需重跑。

### 2.3 Java / Hadoop（仅 ETL 需要）
- JDK 11，路径不含空格（本机 ETL 用 `C:/jdk11`；当前系统 `JAVA_HOME` 指向 Temurin 11）。
- `HADOOP_HOME` 指向 `D:/DataMind/hadoop`（解决 Windows 本地文件系统报错）。
- MySQL Connector/J 8.4.0 jar：联网时 Spark 自动下载；离线时设置环境变量 `MYSQL_JDBC_JAR` 指向本地 jar。

### 3.4 评论语义洞察
问法示例：`低分评论主要在抱怨什么？`、`物流破损相关评论有哪些？`。

- 首次提问时从 `data/raw/` 的 5 个 Olist CSV 懒加载构建本地 SQLite FTS5 索引，默认路径 `data/review_index/reviews.sqlite3`；约 9.9 万条评价在本机首次构建约 2–3 秒。
- 数值结论由索引内的参数化 SQL 聚合得到；评论主题由跨语言查询扩展后的 BM25/RRF 检索原文，再交给模型基于召回证据总结。
- 回答中的 `[R1]` 等编号可跳转到对应原文，引用包含 `review_id`、`order_id`、评分、日期和品类。
- 索引由源文件路径、大小和修改时间共同校验，源 CSV 变化后自动原子重建；索引目录已加入 `.gitignore`。
- 该功能不修改 MySQL 数仓，也不需要重跑 ETL 或单独部署向量数据库。

## 4. 配置说明

### 4.1 配置文件位置
- 真实凭据：`agent/.env`（已加入 `.gitignore`，不入库、不外传）。
- 示例模板：`agent/.env.example`（仅占位值）。
- 代码读取：`agent/config.py`（Agent）、`backend/db/connection.py`（指标接口）。两者加载同一份 `agent/.env`。

### 4.2 环境变量与优先级
优先级：**进程环境变量 > agent/.env 文件 > 代码默认值**。
`agent/config.py` 与 `backend/db/connection.py` 均用 `override=False` 加载 `.env`，即显式设置的环境变量优先。

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | 是 | 空 | 模型密钥；缺失时明确报错且不回显 |
| `DEEPSEEK_BASE_URL` | 否 | `https://api.deepseek.com` | 模型接口地址 |
| `DEEPSEEK_MODEL` | 否 | `deepseek-chat` | 模型名 |
| `DATAMIND_LLM_CONNECT_TIMEOUT` | 否 | `10` | 模型连接/写/池超时（秒） |
| `DATAMIND_LLM_READ_TIMEOUT` | 否 | `45` | 模型读取超时（秒） |
| `DATAMIND_LLM_MAX_RETRIES` | 否 | `1` | SDK 最大重试次数（有界） |
| `DATAMIND_QUERY_USER` | 是 | `datamind_ro` | 只读查询账号 |
| `DATAMIND_QUERY_PASSWORD` | 是 | 空 | 只读查询密码；缺失时明确失败，不用空密码连接 |
| `DATAMIND_MYSQL_HOST` | 否 | `localhost` | MySQL 地址 |
| `DATAMIND_MYSQL_PORT` | 否 | `3306` | MySQL 端口 |
| `DATAMIND_QUERY_TIMEOUT_MS` | 否 | `15000` | 单次查询超时（MySQL MAX_EXECUTION_TIME） |
| `DATAMIND_BACKEND_URL` | 否 | `http://localhost:8000` | Agent 回调数据字典服务的地址 |
| `DATAMIND_REVIEW_INDEX_PATH` | 否 | `data/review_index/reviews.sqlite3` | 评论洞察本地索引路径；由 `agent/review_store.py` 读取 |

### 4.3 两类账号的区别
- **ETL 写入账号**：写在 `etl/*/build_*.py` 脚本顶部配置区（本机为 root），用于建库/建表/写入，**仅 ETL 使用**。
- **查询只读账号** `datamind_ro`：仅 7 张 ADS/DWS 表的 SELECT，供指标接口与 Agent 使用；
  执行时另加 `SET SESSION TRANSACTION READ ONLY` 与 `MAX_EXECUTION_TIME` 双保险。
- 两者分离；只读账号初始化见 `docs/mysql_readonly_init_template.sql`。

> 说明：ETL 脚本按原任务保留各脚本顶部的写入连接配置，因此**不能声称整个仓库无明文凭据**；
> 本轮返修只保证 Agent/后端侧无真实凭据，真实凭据集中在被 gitignore 的 `agent/.env`。

### 4.4 首次部署步骤
1. 复制 `agent/.env.example` → `agent/.env`，填写 `DEEPSEEK_API_KEY`、`DATAMIND_QUERY_PASSWORD`。
2. 按 `docs/mysql_readonly_init_template.sql` 创建只读账号并授权（替换密码占位符）。
3. 确认 `backend/data_dictionary.py` 的 7 张表与 SQL 模板授权表一致（白名单唯一来源）。
4. 启动后端（第 3.1 节），`curl /health` 与四个指标接口验证。

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 问数报“数据库连接失败，请检查 MySQL 服务是否已启动” | MySQL 未启动或端口错误（错误码 2003）；检查服务状态与 `DATAMIND_MYSQL_PORT` |
| 报“未配置 DATAMIND_QUERY_PASSWORD” | `agent/.env` 缺查询密码或环境变量未生效；补齐后重启服务 |
| 报“模型服务暂时不可用” | `DEEPSEEK_API_KEY` 缺失或模型接口超时；检查密钥与网络 |
| 报“当前数据能力无法精确回答” | 问题超出汇总表能力（如自定义期间去重用户数），属预期的能力限制，非故障 |
| 报“查询被安全策略拒绝” | SQL 命中非授权表/锁语句/多语句；仅支持 ADS/DWS 授权表只读统计 |
| 报“评论索引暂时不可用” | 检查 `data/raw/` 下评论、订单、商品、商品明细和品类翻译 5 个 CSV 是否完整，以及索引路径是否可写 |
| `caching_sha2_password` 认证失败 | 确认已安装 `cryptography`（见 2.1） |
| Spark 报表不存在或 JDBC 驱动缺失 | 设置 `MYSQL_JDBC_JAR` 指向 Connector/J 8.4.0 jar，或联网自动下载 |
| 环境变量改了没生效 | `.env` 不覆盖已存在的环境变量；检查是否有同名系统环境变量，改后重启服务 |
