## 🔍 曾经的问题：问数"所有查询返回空"——两轮排查实录

### 症状（已修复）
所有问题都返回 0 行结果，SQL 为 `SELECT '未找到相关数据' AS message;`，
或返回 200 但 `row_count=0`、回答"未查询到相关数据"。

### 根因复盘（共三个，均已于 2026-11-16 ~ 11-17 修复）

| # | 根因 | 位置 | 修复 |
|---|------|------|------|
| 1 | `async def chat` 里同步调用 `agent_graph.invoke`，阻塞事件循环；Agent 内部 HTTP 回调本服务 `/api/schema/search` 永远得不到响应，Schema 检索必然拿到空结果 | `backend/api/chat.py` | 用 `run_in_threadpool` 包裹 `invoke` |
| 2 | `/api/metrics/trend` 的 `year_month` 是 MySQL 保留字，SQL 未加反引号 | `backend/api/metrics.py` | 所有保留字列加反引号 |
| 3 | MySQL 服务启动类型为 Manual，重启机器后不自启，SQL 执行全部连库失败，但旧文案统一答"未查询到相关数据"，误导排查方向 | 环境 + `agent/nodes/response.py` | 见下方"启动 MySQL"；响应节点现在会区分连接失败/SQL失败/空结果 |

### 排查顺序建议（5 分钟）

1. **先看 MySQL 活不活**（历史教训：先查基础设施，再查代码）

```bash
netstat -an | findstr :3306
# 未监听 → 先启动 MySQL（见下）
```

2. **测试后端 Schema 接口是否正常**

```bash
curl http://localhost:8000/health
curl "http://localhost:8000/api/schema/search?q=GMV"
```

✅ 返回表列表 → 后端数据字典正常
❌ 为空/超时 → 若 FastAPI 在运行，检查数据字典 `backend/data_dictionary.py`

3. **用 chat 接口实测并看返回的 SQL 与回答**

```bash
curl -X POST http://localhost:8000/api/chat -H "Content-Type: application/json" -d "{\"question\": \"总GMV是多少\"}"
```

现在的错误信息可以直接区分三种情况（2026-11-17 起）：
- 回答含 **"数据库连接失败"** → MySQL 没启动或账号问题，回答里带错误码
- 回答含 **"SQL 执行失败（已自动重试仍未成功）"** → 生成的 SQL 有语法/字段问题，看附带错误
- 回答含 **"查询执行成功，但没有匹配到任何数据"** → 链路全通，是查询条件与数据不匹配

### 启动 MySQL

mysql 服务启动类型目前是 Manual（需要管理员改为自动）：

```powershell
# 管理员 PowerShell：
sc.exe config mysql start= auto
net start mysql
```

无管理员权限时的临时方案（控制台方式，关闭终端即停）：

```bash
D:\mysql\mysql-8.4.11-winx64\bin\mysqld.exe --defaults-file="D:\mysql\mysql-8.4.11-winx64\my.ini" --console
```

注意（2026-11-17 实测）：`cryptography` 包必须已安装在运行 FastAPI 的 Python 环境里
（aiomysql 在 MySQL 8 caching_sha2_password 完整认证路径上的硬依赖），
否则 MySQL 冷启动后第一次连接会报：
`'cryptography' package is required for sha256_password or caching_sha2_password auth methods`。
该包已加入 `backend/requirements.txt`。**安装依赖后必须让 uvicorn 重启 worker**
（`--reload` 默认只监听 .py 文件，改 requirements.txt 不会触发，需 touch 一个 .py 文件）。
