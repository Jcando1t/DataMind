### 1. 数据层（ODS → DWD → DWS → ADS）

**路径**：`D:\DataMind\etl\`

#### 文件清单
- `ods/load_ods.py` - 原始数据层：从 CSV 加载 8 张表到 `datamind_ods`
- `dwd/build_dwd.py` - 明细数据层：清洗去重，构建 4 张明细表
- `dws/build_dws.py` - 汇总层：按日、品类、卖家汇总，6 张表

#### 关键技术
- **去重逻辑**：DWD 用窗口函数处理同一用户多个 customer_id
- **月度补齐**：DWS 自动填充缺失月份，环比增长率正确处理上月为零的情况（上月为 0 → NULL）
- **自动建库**：使用 JDBC 驱动直连 MySQL，无需手动建库

### 3. LangGraph Agent

**路径**：`D:\DataMind\agent\`

#### 节点设计（状态机）

```
用户问题
  ↓
[意图判断] intent.py（结合历史，追问可正确归类）
  ├─ data_query → [Schema检索] schema_retrieval.py
  │                    ↓
  │              [SQL生成] sql_generation.py（要求 `库名`.`表名` 全限定）
  │                    ↓
  │              [SQL执行] sql_execution.py（sql_guard 结构校验 + 只读账号 + 有界提取）
  │                    ├─ 成功 → [响应决策] response.py
  │                    ├─ SQL 失败 → 重试（最多 2 次）→ response.py
  │                    └─ 连接失败（错误码 2003 等）→ 不重试，直接明确报错
  └─ chitchat → [闲聊处理] response.py (chitchat_node)
```

#### 2026-11-17 加固内容（全部有回归测试，见 `agent/test_fixes.py`）

1. **chat_history 修复**：原状态定义用 `operator.add` 累加器且节点返回完整 state，
   历史每过一个节点翻倍；已改为普通覆盖语义，由调用方维护历史
2. **Schema 检索异常不静默**：单关键词失败记录告警；全部失败抛 RuntimeError，
   由 chat 接口返回明确错误，不再"拿空 Schema 生成兜底 SQL"造成假成功
3. **跨库引用修复**：SQL 要求全限定 `库名`.`表名`；连接不绑定单一库；
   执行前按 Schema 上下文自动为裸表名补全前缀（ads/dws 跨库查询天然支持）
4. **只读与行数上限硬限制**（不依赖提示词）：仅单条 SELECT；拦截写操作、
   多语句、注释藏毒、文件读写、系统库访问；无 LIMIT 自动追加 / 超大 LIMIT 截断为 1000；
   fetch 层 1000 行兜底
5. **三类情况明确区分**：数据库连接失败（不重试，明确提示检查 MySQL）/
   SQL 失败（重试耗尽后给出具体错误）/ 执行成功但空结果（提示调整问法）
6. **图表维度修复**：x 轴自动取第一个非数值列（不再把 rank 序号当维度）；
   饼图取占比列、柱状图取数值度量列；"前N名"（含中文数字）触发排行图表
7. **追问支持**：意图判断结合历史；关键词提取不到时回退用历史最近一条用户消息提取
   （"那前三名呢？"实测正确命中品类排行表）

#### 2026-11-17 独立验收返修（详见《返修报告-2026-11-17.md》）

独立验收复现的 4 类问题已按"结构校验 + 最小权限账号"整改，不再依赖字符串黑名单：

1. **只读边界**：新增 `agent/sql_guard.py`，用 sqlglot（MySQL 方言）解析语法树后
   做结构判断——单条查询、禁 `SELECT ... INTO`（含换行写法）、禁系统库
   （含反引号写法）、禁非授权表、禁加锁读、禁系统变量、禁危险函数；
   解析失败一律拒绝（fail closed）
2. **专用只读账号**：新建 `datamind_ro`（仅 7 张 ADS/DWS 授权表 SELECT，无 FILE/写权限），
   Agent 与指标接口都改用它；ETL 保留原 root 写入配置不变。
   执行时另加 `SET SESSION TRANSACTION READ ONLY` 与 `max_execution_time=15s` 双保险
3. **行数上限**：只对最外层加/收紧 LIMIT，覆盖 `LIMIT n` / `LIMIT off,n` / `LIMIT n OFFSET off`，
   子查询内 LIMIT 与字符串里的 "limit 1" 不干扰；改用流式游标 `SSDictCursor` +
   `fetchmany(1001)` 有界提取，不再 `fetchall` 后切片；顶到上限时标记 `result_truncated`
4. **总结完整性**：≤100 行（趋势 25 行、品类 72 行、Top20）全量交给模型；
   更大的结果集做首尾+极值抽样，并在提示词与用户可见回答里明确标注数据范围
5. **金额口径**：统一为巴西雷亚尔（BRL / R$），提示词禁止使用"元""人民币"
6. **失败状态**：连接失败 → HTTP 503 + code 503；SQL 重试耗尽 → 500/500；
   被安全策略拒绝 → 400/400；成功空结果保持 200。响应做了凭据脱敏
7. **凭据外置**：API Key 与只读账号密码迁到 `agent/.env`（已 gitignore），
   源码与文档不含真实凭据，附 `agent/.env.example`
